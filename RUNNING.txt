MiniVectorDB 运行与复现

快速开始（宿主机只需 Docker 和 Bash）
在 2026-competition-round2 仓库根目录执行：
  bash scripts/reproduce.sh check
自动从源码构建 linux/amd64 镜像，并在禁网、2 CPU、128 MiB、无 swap
容器中执行最新官方5组公开用例。报告：artifacts/team/public-report.json。
本机无需安装 Python、NumPy、GCC 或 Python 头文件。

回归检查：bash scripts/reproduce.sh unit（或 make container-test）。
运行示例：bash scripts/reproduce.sh run < examples/basic.sql
首次示例使用空数据卷，默认卷名 minivectordb-team-data；可通过
MINIVECTOR_VOLUME 指定另一卷。程序数据统一写入容器 /data。
再次执行 run 使用同一数据卷，已提交内容保留。不要重复执行示例中的建表。

离线分享给队友
  bash scripts/reproduce.sh export
生成 artifacts/minivectordb-image.tar.gz。队友取得相同源码版本和该镜像后：
  bash scripts/reproduce.sh load /路径/minivectordb-image.tar.gz
  MINIVECTOR_SKIP_BUILD=1 bash scripts/reproduce.sh check
  MINIVECTOR_SKIP_BUILD=1 bash scripts/reproduce.sh run
离线模式复用导入镜像，省去基础镜像、apt 和 pip 下载。
默认镜像 minivectordb:team，可通过 MINIVECTOR_IMAGE 指定其他名称。
构建时可通过 MINIVECTOR_PIP_INDEX_URL 指定公共 PyPI 镜像；wheel 哈希仍校验。

依赖与构建
Python 3.12.8 基础镜像锁定 SHA256；GCC 12.2、libc 开发包及其37个安装/
升级包锁定在 debian-packages.lock，来自固定 Debian 快照。
NumPy 2.0.1 及44个发布 wheel 哈希锁定于 requirements.lock，只安装二进制
wheel。NumPy用于数组和数学运算；存储、SQL执行、索引和事务由本项目实现。
C内核从 native/topk.c 编译，运行镜像不包含编译器。Dockerfile为多阶段构建。
纯手工构建/启动：
  docker build --platform linux/amd64 -t minivectordb:team .
  docker run --rm -i --network none -v minivectordb-team-data:/data minivectordb:team

SQL与交互
python3 -m minivectordb 和 python3 -m minivectordb.server 均启动SQL入口。
stdin接收分号结束的SQL，支持多行、Unicode及双单引号转义；前台持续运行。
支持建表、BIGINT主键、VARCHAR(n)、VECTOR(n)、多行INSERT、SELECT、
UPDATE、DELETE、比较条件/AND、ORDER BY、LIMIT、L2_DISTANCE及向量索引。
向量支持题面的带引号JSON数组，如 '[1,0]'，同时保留裸数组语法。
VARCHAR中的数组形字符串仍作为字符串。向量拒绝维度错误、bool、NULL、
非有限值和float32溢出；按float32存储。字符串长度和排序使用Unicode码点。
不支持的SQL返回错误。默认exact；--mode ann当前复用精确检索。
本地结果格式：LOCAL_SQL_READY；查询列名帧、行帧和完成帧；错误ok=false。
小结果一次刷新，大结果分块刷新。诊断写stderr；EOF或SIGTERM正常退出，
回滚未提交事务。SIGKILL后重启复用/data。无需端口或网络监听。

存储、索引和事务
不可变二进制行段、附尾部的有序主键目录、原子manifest构成持久化状态。
追加插入，定期合并；更新/删除流式重写。提交先同步数据与索引文件，
再同步并替换manifest，最后同步目录，完成后确认成功。失败语句恢复至
语句前视图；BEGIN/COMMIT/ROLLBACK支持读己之写。恢复清理未提交孤立文件。
向量索引自行实现；精确检索先过滤再TopK，距离并列按主键升序。
原生标量/AVX2内核、mmap、位置列表、保守误差界的.q8筛选用于加速。
映射缓存8MiB、过滤缓存2MiB、标量缓存4MiB；大数据分块处理和外部排序。
索引更新采用整表重建；.q8为可选压缩筛选文件，最终距离来自原float32向量。

验证与正式接口状态
官方公开用例来自 a3dba559c1e7ebdc48bc990ffb1a4c75d1c1075c，文件保持原样，
位置 mysqltest/。check比较所有列名、受影响行数、记录、顺序及浮点距离。
当前公开用例5/5通过，共32条SQL；容器回归67项通过。
官方 mysqltest/README.md 明确公开用例未定义进程通信封装。
正式通信协议、错误码、退出/模式约定及冻结资源配置仍待官方发布，
当前LOCAL_SQL_READY和结果帧是本地适配层。公开用例验证与正式准入分开记录。

开发与完整本地测评（可选）
宿主机使用CPython 3.9～3.12时：
  python3 -m venv .venv
  .venv/bin/python -m pip install -r requirements.txt
  make evaluate PYTHON=.venv/bin/python
完整评测包含容器回归、材料格式、官方公开用例、自有SQL/恢复用例、三轮
性能及超内存资源负载。结果进入artifacts/。资源检查默认要求原始
memory.peak<=memory.max、无OOM、无swap；保留原始I/O与峰值，不裁剪。
自测性能记录及历轮改动见 WORK_SUMMARY.txt；本次逐项审核见 COMPLIANCE.txt。
