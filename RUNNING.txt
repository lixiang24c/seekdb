MiniVectorDB 完整重写版本

开发分支：minivectordb-rewrite
官方协议基点：f4d4e26653af823a7601668802f80e374ad6643c
协议与检查器：STDIO_PROTOCOL.md、protocol_check/、mysqltest/ 保留官方原文件。
语言：Python 3.12.8；仅标准库。基础镜像按Dockerfile中的digest锁定。
构建不运行apt/pip，不依赖本地二进制，运行时不联网。

构建与正式入口
docker build --platform linux/amd64 -t minivectordb:rewrite-complete .
docker run --rm -i --network=none --cpus=2 --memory=2g --memory-swap=2g --pids-limit=128 --read-only --cap-drop=ALL --security-opt=no-new-privileges -v minivectordb-rewrite-data:/data minivectordb:rewrite-complete

默认前台入口为 python3 -B -u -m minidb.server /data，不需要补充启动参数。
启动先读取并校验已提交目录和数据文件，然后主动输出 {"type":"ready"}。
stdin/stdout为UTF-8 JSONL；每次响应立即flush；诊断只写stderr。
shutdown回滚未提交事务，返回原id和ok:true，以退出码0结束。EOF同样回滚并正常退出。
所有数据、目录、索引、事务暂存及查询临时文件都在/data。
默认以root运行。官方绑定目录示例要求宿主数据目录chmod777；命名卷使用镜像/data权限。

SQL与检索
支持CREATE TABLE、BIGINT主键、VARCHAR(n)、每表最多一个VECTOR(n)，INSERT多行及列清单、SELECT投影、UPDATE、DELETE。
支持比较=、<、<=、>、>=，AND、ORDER BY多键与ASC/DESC、LIMIT，以及L2_DISTANCE和过滤后精确TopK。
VARCHAR按Unicode码点计数和排序；BIGINT保留有符号64位精度；向量入库及查询参数均转为有限float32。
并列排序按主键升序；不支持的语句在执行前拒绝。UPDATE affected_rows按匹配行数返回。
CREATE VECTOR INDEX建立自实现磁盘平面索引，保存主键与float32向量；exact和ann均可得到精确结果。
无过滤的距离TopK可以使用平面索引；有过滤时先过滤再检索。索引和记录由同一提交发布，回滚及重启状态一致。
错误返回ok:false及非空error.code；语法/类型/主键错误后继续接收请求。持久化I/O失败记录stderr并退出，重启重新读取提交状态。

启动后发送以下每行一个JSON对象：

存储与提交设计
记录文件按主键排序，使用长度前缀和变长二进制字段；无单页行长度限制。向量保存为小端float32。
INSERT先校验批内及已有主键，再写独立有序数据段；主键范围不重叠时跳过查重扫描，否则用磁盘定宽主键索引二分查找。
数据段按层级归并，避免每批都重写全表；归并直接复制记录二进制，并同步写向量索引段。段数随写入批次数按对数增长。
UPDATE和DELETE仍流式生成表的新版本。语句失败时删除该语句的新文件，保留事务此前成功语句。
显式事务使用私有目录视图，读取自己的记录和索引版本；ROLLBACK恢复已提交视图。
COMMIT先fsync全部新文件及文件名，再fsync新manifest，原子替换manifest.json并fsync目录，然后回复成功。
多表修改一次发布。自动提交使用相同机制。进程强杀后只需读取完整旧manifest或完整新manifest，未引用的文件回收；回收中再次退出可以重做。
查询使用流式扫描、受内存预算约束的TopK堆；普通排序或大K使用/data分段归并。响应先完成查询，再流式输出JSON，避免错误后输出半份成功结果。
查询只解码实际使用的列，先检查普通列过滤条件再处理向量；TopK候选保留二进制记录，确定结果后才解码输出字段。
距离候选使用math.dist做带宽余量的排除检查，入选候选仍按原math.fsum平方距离和主键排序；不是近似剪枝。
主键升序读取直接使用数据段的有序归并，LIMIT满足后停止，不再扫描全部记录维护排序堆。

当前取舍
INSERT采用分段写入及分层归并；UPDATE/DELETE仍顺序生成整表新版本，磁盘需容纳提交前后版本及归并临时段。
索引采用精确线性扫描，不作近似剪枝。已完成批量写入与查询解码/TopK候选处理的两阶段优化。
本地64MiB压力条件与官方公开2GiB配置分开记录。正式成绩由平台对指定提交评测产生。
