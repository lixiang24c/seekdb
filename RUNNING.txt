MiniVectorDB 运行与复现

快速开始（宿主机只需 Docker 和 Bash）
在 2026-competition-round2 仓库根目录执行：
  bash scripts/reproduce.sh check
自动从源码构建 linux/amd64 镜像，并在禁网、2 CPU、128 MiB、无 swap
容器中执行最新官方20组公开用例（95条SQL）。报告：artifacts/team/public-report.json。
本机无需安装 Python、NumPy、GCC 或 Python 头文件。

回归检查：bash scripts/reproduce.sh unit（或 make container-test）。
十万SQL生成与回放：bash scripts/reproduce.sh stress（或 make stress）。
默认随机种子20261109、128个生成场景，另含20组官方样例；SQL与预期结果保存为
gzip JSONL，逐条独立模型核对。Docker入口使用256MiB容纳测试驱动和数据库，
其耗时与内存不作性能成绩。失败场景可通过scripts/stress.py run --case重放。
完整性能对照、十万SQL和故障复现结果见 PERFORMANCE_COMPARISON.txt。
正式协议示例：bash scripts/reproduce.sh run < examples/basic.jsonl
首次示例使用空数据卷，默认卷名 minivectordb-team-data；可通过
MINIVECTOR_VOLUME 指定另一卷。程序数据统一写入容器 /data。
再次执行 run 使用同一数据卷，已提交内容保留。不要重复执行示例中的建表。

离线分享给队友
  bash scripts/reproduce.sh export
生成 artifacts/minivectordb-image.tar.gz。队友取得相同源码版本和该镜像后：
  bash scripts/reproduce.sh load /路径/minivectordb-image.tar.gz
  MINIVECTOR_SKIP_BUILD=1 bash scripts/reproduce.sh check
  MINIVECTOR_SKIP_BUILD=1 bash scripts/reproduce.sh run
离线模式复用导入镜像，省去基础镜像、apt 和 pip 下载。
默认镜像 minivectordb:team，可通过 MINIVECTOR_IMAGE 指定其他名称。
构建时可通过 MINIVECTOR_PIP_INDEX_URL 指定公共 PyPI 镜像；wheel 哈希仍校验。

依赖与构建
Python 3.12.8 基础镜像锁定 SHA256；GCC 12.2、libc 开发包及其37个安装/
升级包锁定在 debian-packages.lock，来自固定 Debian 快照。
NumPy 2.0.1 及44个发布 wheel 哈希锁定于 requirements.lock，只安装二进制
wheel。NumPy用于数组和数学运算；存储、SQL执行、索引和事务由本项目实现。
C内核从 native/topk.c 编译，运行镜像不包含编译器。Dockerfile为多阶段构建。
纯手工构建/启动：
  docker build --platform linux/amd64 -t minivectordb:team .
  docker run --rm -i --network none -v minivectordb-team-data:/data minivectordb:team

SQL与正式JSONL交互
默认入口python3 -m minivectordb、.server及Docker均采用官方STDIO_PROTOCOL.md。
启动完成恢复后主动输出 {"type":"ready"}，随后逐行接收execute/shutdown JSON。
execute请求包含id、op、sql、search_mode；SQL字符串内的分号和换行由JSON转义。
每个请求只返回一行JSON，原样回传id及类型，ok为布尔值。查询返回columns/rows，
修改返回affected_rows；错误为error.code/message，失败后可继续请求。
shutdown先回滚未提交事务并落盘，再回复id/ok:true，flush后以0退出，无附加输出。
所有日志写stderr，数据及大结果暂存均位于/data。容器根文件系统可以只读。
支持BIGINT、Unicode VARCHAR、float32 VECTOR、增删改查、过滤、排序、TopK、
向量索引、事务和恢复。exact/ann均采用精确检索，按每个请求的search_mode选择。

官方工具无需pip依赖，宿主Python3.9+和Docker即可使用：
  python3 protocol_check/run.py --image minivectordb:team --handshake-only \
    --output artifacts/official-handshake-new
  python3 protocol_check/run.py --image minivectordb:team \
    --output artifacts/official-public-new
每次使用新产物目录。工具按实际交互顺序检查，并使用只读根文件系统、禁网、
2 CPU、2 GiB、128 PID限制运行实际Docker默认入口。
历史纯SQL工具使用显式 --protocol local 参数，保留LOCAL_SQL_READY与多帧结果；
此参数用于开发兼容，正式判题使用默认JSONL，不需要额外启动参数。

存储、索引和事务
不可变二进制行段、有序主键目录、全库database.wal与检查点manifest构成持久化状态。
追加插入并分层合并。小范围更新保存替换版本，删除保存有序主键墓碑；最多8层
差量，单次变更超过max(64,当前行数/4)时合并。索引查询排除旧版本并合并当前
差量；同一事务内普通查询与向量检索看见相同状态，回滚恢复原视图。
提交将新文件内容按256KiB帧追加WAL，再写全库catalog提交帧；fdatasync成功后
才确认，普通提交一次同步。WAL达到8MiB或正常关闭时做同步检查点：同步当前
文件、原子发布manifest、同步目录，再清空WAL。大事务可暂时超过8MiB阈值。
启动先校验帧并重放完整提交，丢弃未完成尾部；完成检查点及孤立文件清理后就绪。
恢复再次被终止时可从同一WAL重复恢复。旧manifest与行格式保持可读。
默认向量索引连续保存主键、记录偏移和唯一的float32向量；行文件保存标量与
向量位置引用，避免再存一份原向量，并保留连续SIMD扫描。标量/AVX2均采用
双精度累加；比较值接近到可能受舍入影响时，用整数表示的原始数值精确复核，
仅真实等距时按主键升序。部分距离剪枝、量化筛选和NumPy候选筛选保留误差边界，
防止提前丢掉应入选的记录。分块结果、事务差量及普通距离排序共用同一比较规则。
过滤先于TopK。旧行格式、连续向量索引
及可选.q8筛选文件继续可读；.q8只用于保守筛选，最终距离取原向量。
映射缓存8MiB、过滤位置/位图缓存2MiB、标量缓存4MiB；大数据分块处理和外部排序。
Python合并堆为保留的候选保存向量及惰性精确比较值，内存随K和维度增长；
大量不同向量等距或极近时会增加精确复核开销，常规距离分离明显的查询保持快速路径。
